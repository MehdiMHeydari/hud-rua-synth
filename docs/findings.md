# Findings (capability profile notes)

Bullets only. Each: what, evidence (trace/job), why we think it happens.

- **Depth from one angled view: luna can't.** lift_cube, shoulder cam only, 30 steps: 0/10 ([job](https://www.hud.ai/jobs/b8c854ade80749ab84a272d5a40f1de4)). In the trace read in full, every grasp was at x=0.35-0.44 while the cube is at x=0.50; it made lateral fixes when the error was depth. Likely monocular depth ambiguity along the camera axis.
- **Ignores proprioception that says the grasp failed.** After each close the state read gripper≈0.007 (fingers met, nothing held). Never used it; only noticed misses after lifting and looking, costing 3-4 moves per attempt.
- **Honest about failure.** Ended with "I wasn't able to pick up the red cube" rather than claiming success (contrast: research reports 24-39% false success claims in stronger models).
- **Wrist camera fixes localization, exposes the next failure.** lift_cube with WRIST=1: still 0/10 ([job](https://www.hud.ai/jobs/94f4ec70d4074857bfd09d43c495c4fe)). In the trace read in full, it now finds the right x (0.50 vs 0.35-0.44 shoulder-only), so depth was the first bottleneck.
- **Knocks the cube askew and never re-orients.** Early off-center closes spun the cube; later closes stopped at gripper≈0.81 (corners, not faces) and the lift slipped. Reproduced in sim: a 45°-rotated cube gives opening 0.88 and fails to lift; 0-20° lifts fine. The agent never changed yaw in 30 moves. It did read the partial-close value ("may indicate edge contact") but didn't infer rotation.
- **Top-down + wrist + grasp line: lift_cube goes 0/10 -> 2/10** ([job](https://www.hud.ai/jobs/952302cc3c93422da3e91e5ed5745048)), inside the 5-30% band. Read one success in full: real (pinched at gripper 0.63 = cube width, lifted to 21 cm). It used the top view for x/y ("image-up is +x") and the grasp line to detect misses immediately ("fingers met without an object... reopening"), instead of lifting to check.
- **Wrist camera offset misleads.** The wrist camera sits ~7 cm to the side of the finger axis, so "cube centred in wrist image" is not "cube between fingers". The agent closed on nothing twice with the cube centred in the wrist view before concluding "the wrist-camera centering is misleading" and switching back to the top view. Real wrist cams are offset too; we don't tell the agent the offset. Candidate knob (state it in the notes or not).
- **Harness validated on lift_cube (top+wrist+grasp line).** Scripted oracle through the real tool: 10/10 ([job](https://www.hud.ai/jobs/5d73def4b1ed41cc9354306a0f23dd81)). gpt-6-sol: 8/10 ([job](https://www.hud.ai/jobs/fa0d8c648df744df8de89e7e444be81e)). gpt-6-luna: 2/10. So the setup can be solved and a mid-tier model mostly solves it; luna's low rate is mostly luna, not the harness.

Any agent that rotated the gripper before grasping was set up to fail regardless of skill. Fixed before task generation; worth a line in the capability-profile caveats.
